# Proposal: bc-side seam upstream anchor — the spec declares the seam, pd consumes it (Option A)

> Status: **PROPOSAL — csr-converged (substantive_converged: true, 12 rounds, record: [seam-upstream-anchor.convergence-record.json](seam-upstream-anchor.convergence-record.json)), NOT yet implemented.** Follows the pd-side P7/P8 landing (tdd-seam-tracer-bullet.proposal.md + ADR #56) whose bc non-goal deliberately left this hole. Label conventions (defined here, first use): Option A = this proposal, the bc-side upstream anchor; Option B = the pd-only choice ADR #56 records as "Architecture choice (recorded): bc carries NO seam field — the seam is a pd-side DERIVATIVE" (recorded in the working-tree ADR #56 amendment; uncommitted — lands with this proposal's commit).

## Context

The P7 landing put the seam in pd only: each Intent-Blueprint AC line freezes its `seam:` at Phase 0, with the pd Planner DERIVING the seam from bc's spec AC (the rich path — derive, don't re-imagine). bc was an explicit non-goal. ADR #56 (Option B) then recorded the architecture choice with three stated consequences: derivation quality = one LLM act (coverage-noted, not gate-enforced); a wrong-boundary AC survives bc's plan-reviewer and surfaces only at pd's reviewer check (g) — the seam-conformance check in pd convergent-loop.md's reviewer prompt template item 3 — one stage later; bc author and pd Planner share the same-family blind spot.

The wiki's upstream-anchoring point says where the seam belongs: the seam list is negotiated and frozen at the SPEC stage (wiki `test-seam` §AI 编码中的接缝纪律 · 上游冻结: a guard whose precondition is never anchored upstream silently degrades). mattpocock's to-spec IS that anchor — "规格与接缝协商（to-spec）：产出规格，同时协商并冻结测试接缝" (wiki `mattpocock-skills` §链条与人工确认门). In the specify→implement pipeline, **bc is the spec stage** — Option A moves the anchor to where the doctrine says it belongs.

## Gap (verified 2026-08-24)

- bc docs: zero Feathers-seam hits (the "seam" hits in bc's `design-decisions.md` are the metaphorical layer-boundary sense — the deterministic/non-deterministic split — not the Feathers test seam).
- `plan-model.schema.json`: no `seam` / `boundary` / `observable` / `acceptance-criteria` field; spec ACs are free-form content in the spec artifact, consumed via the queue's authority chain (NOT via item `dod_ref` — that field is a DoD pointer, not an AC pointer).
- `plan-reviewer.agent.md`: four defect kinds (gap / over-engineering / contradiction / blind-spot); no seam-quality dimension.

## Proposed fix (4 edit points)

### 1. bc `arch-design.md` §3 + `SKILL.md` — the spec's acceptance-criteria section is DEFINED bc-side, and each spec AC gains the seam declaration

Two parts — the attachment point must be landed first: bc NAMES the spec's anchor sections (its constraints registry `infra/scripts/constraints.json` product-spec profile anchors include `acceptance-criteria`, with bilingual detection aliases) but defines NO AC-ENTRY shape — bc has no spec template and no per-AC content format; the AC-ENTRY shape (and the seam tail on it) is what this fix lands:

- **(1a) the AC-ENTRY shape definition lives in bc `arch-design.md` §3** — the authoritative per-type artifact contract (SKILL.md:95: "docs/arch-design.md = authoritative spec"): the product-spec anchor entry gains the AC-ENTRY shape (per-AC entries, existing free-form shape, NO BDD shape or AC-x id scheme imposed on bc; the BDD refinement is the BLUEPRINT's downstream act per pd intent-blueprint.md: "spec `acceptance-criteria` → Blueprint AC, refined into BDD Given/When/Then"). bc `SKILL.md` REFERENCES it (one line, not a duplicate definition).
- **(1b) each spec AC gains the seam tail**:

```text
<existing spec AC text> — seam: <public-boundary-name> (catches: <what this boundary verifies>; misses: <what it does not>)
```

The seam is the substitution point — where behavior can change without editing the code (Feathers: "a place where you can alter behavior in your program without editing in that place", *Working Effectively with Legacy Code* 2004 ch.4); the name is the public boundary the caller actually uses, never an internal helper. The catch/miss clause is required, not optional (a bare name is label-blind-picking — wiki `test-seam` §权衡与局限 · 接缝选择摩擦). Declared at spec stage — the upstream anchor becomes real. Precedence: when the pd refinement's inferred boundary differs from the declared seam, the DECLARED seam wins (upstream anchor authority) — pd derives only when the spec AC carries no seam. Scoping sentence (the precedence/refusal discriminator): the precedence rule governs differences among legitimate PUBLIC-boundary choices; a declaration failing the public-boundary or observability criterion is NOT a precedence case — the Planner refuses and escalates (the refusal rule applies). Three states, named distinctly: absent-SPEC-seam → pd derives (fallback, coverage-noted — the pre-Option-A behavior); absent-BLUEPRINT-seam → the pd absent-seam degrade (a different state, unchanged — NOT expected on this path: latch and derive both land a seam, but a missed latch is the coverage-noted LLM-act risk, so "never fires" is not claimed); declared-but-WRONG seam — two sub-cases with DIFFERENT catches, named honestly: (i) internal-helper name — the primary catches are bc Fix 2(a) (the boundary-is-public check) and the pd Planner's PRE-freeze refuse-to-freeze; POST-freeze, check (g) is NOT a detector for this sub-case (tests written AT the declared internal helper CONFORM — a conforming-wrong-seam hole, stated honestly, rule 3); (ii) boundary the AC's observable outcome cannot be observed at — the STRUCTURAL catch is the pd Planner's PRE-freeze refusal; POST-freeze the mechanism is INDIRECT and honestly named: the Coder's tests must relocate to observe the outcome, the relocation is a check (g) conformance violation, and the reviewer raises the pd revision channel's third trigger ("has acceptance criteria that cannot be satisfied" — an AC whose declared seam boundary cannot observe its outcome, intent-blueprint.md Blueprint Revision Channel; the channel's discovery is implementation/review's, the Coder executes the suspend, the Planner is the escalation TARGET). Check (g) itself tests seam-CONFORMANCE, not outcome-observability — it fires only via the relocation, never as a direct observability check (no such check exists at either skill; Fix 2's checks carry none — stated, not overclaimed); PRE-freeze, the pd Planner refuses to freeze and escalates directly (the channel does not apply pre-freeze). Endpoint, named: the blueprint-defect escalation reaches the bc-side re-convergence lifecycle (re-open the spec, correct the declaration, re-freeze, re-latch — the anchor authority forbids fixing the blueprint's seam while the spec still declares the wrong one). Carrier, named (bc has no such lifecycle in-repo today): a bc `SKILL.md` clause defines the re-open path with three stated semantics — (1) TRIGGER: a pd-side wrong-seam escalation (the blueprint-defect flag or the pre-freeze refusal report) naming the spec AC; (2) RE-OPEN: the existing frozen spec re-enters bc's convergence loop as a REVISION (not a fresh artifact), riding EXISTING open carriers — the re-open entry rides an entry in the run-record's `coverage`/`caveats` string-ARRAY fields (the schema is closed, `additionalProperties: false`, with no re-open or spec-version field — stated; no schema change claimed), then the FULL loop re-runs on the corrected spec: re-normalize (corrected spec markdown → regenerated plan-model.json — produce.py takes an already-authored plan-model, not the spec, so the regen step is named explicitly), `produce.py` re-runs, convergence re-checks, and the spec version bump rides a carrier the bc SKILL.md re-open clause DEFINES at landing (bc's current authoritative docs carry NO frontmatter — verified: arch-design.md and iteration-plan.md both start at `# heading` — so the clause introduces the convention, e.g. a `spec-version:` line at the spec top; the CONSUMER of that line is the pd re-latch agent reading the spec text (no bc script parses a per-spec version today — normalizer.py and plan_model.py hardcode plan_model_version "v1"; no bc script edit is claimed, keeping the audit's one-script-entry scope); the convention's exact shape is landing content of the clause, not of this proposal); (3) PROPAGATION: the corrected spec propagates to the running pd task via the authority_chain re-read at the re-latch. STRUCTURAL INVARIANT, stated: the correction is seam-local — the re-frozen `.queue.md` must be structurally identical to the pre-re-open one (same items/deps; only the spec content changed). If the re-convergence diverges structurally (items/deps changed), the fallback is named: pd's queue Revision Channel (`status` -> `revising` -> edit -> version bump -> `frozen`) + `plan_queue.py sync` ("pick up structural changes while preserving status", plan-driven-mode.md) — the structural-divergence path, distinct from the seam-local default. Refactoring runs reconcile with Option A explicitly: a refactoring spec's ACs DECLARE the seam from the locked tests' observed boundary (the tests themselves are the seam evidence — the spec-declares principle extended, not the derive fallback). Check (g) conforms against the corrected declaration, never a wrong frozen one. Severity scoping, corrected: rule 4's advisory doctrine governs the bc-side DETECTION layer (Fix 2's checks, warning severity) AND the pre-freeze refuse-to-freeze — an LLM-act convention, best-effort with no guarantee, coverage-noted per rule 3 (the pre-freeze phase has no loop-state machinery, so nothing deterministic enforces it; the refusal is the Planner's instructed behavior, nothing more). The ONE deterministic machinery state is the post-freeze blueprint-defect suspend (a channel state via `loop_state.py mark-suspend`).

### 2. `plan-reviewer.agent.md` — a seam-quality dimension

Fold a seam check into the existing `gap` / `blind-spot` kinds (no new kind enum — the schema stays untouched). Activation + resolution path, named: the reviewer reviews the frozen plan-model; it reads the spec's `acceptance-criteria` anchor section directly via the authority chain (the constraints.json product-spec anchor is the section's name — NOT via `dod_ref`, which is a DoD pointer, not an AC pointer). The agent's input contract already makes the authority docs conditional ("if provided"); bc `SKILL.md` step 4's spawn instruction gains the matching clause — pass the spec (via the authority chain) to the reviewer — so the active path is the default, not the exception; when the spec is NOT provided, the check degrades to a coverage note (rule 3, inactive — never a false Blocker). For each spec AC declaring a seam, check:

- (a) the boundary is a public interface the caller uses, not an internal helper;
- (b) the catch/miss note is present and non-vacuous;
- (c) an independent truth source exists — two levels, cited separately: the expected-values criterion (expected values must come from an independent source: known-good literal, hand-worked example, spec — wiki `test-seam` §AI 编码中的接缝纪律 · 三种测试反模式 · 同义反复) and the change-level root gap (if the change has no assertable independent truth source, seam tests degenerate to tautology — wiki `test-seam` §权衡与局限 · 根缺口; the no-truth-source case is a flag, not a resolution; the resolution is 异源-oracle territory, same-family ceiling unchanged).

Precision rule unchanged: a Blocker must cite a REAL defect with concrete quotes and an `item_id.field` location. A boundary-choice disagreement without evidence is a warning, never a Blocker (rule 4).

### 3. pd `intent-blueprint.md` rich path — consume, don't derive

When the spec AC carries a declared seam, the Planner **LATCHES** it — latch-grade confidence, per the anchors-map latch notion as an ANALOGY (bc `plan-model.schema.json` `$defs/anchors`: "latch: explicit anchor sections; semantic-infer: inferred"; the seam tail is an explicit marker on a spec AC). No `ref`/anchors-map entry is created at pd — the anchors map is a bc-side plan-model structure at section granularity (normalizer.py: `ref` is the "heading"/"prose" discriminator, not an AC pointer), and the pd Planner reads the SPEC via the queue's authority_chain; the latch is the Phase-0 act, recorded on the blueprint AC line itself. Note the rejected justification: the Phase −1 graded-extraction table (`plan-driven-mode.md` §Phase −1) keys its Latch row to structural/tabular plan signals and governs QUEUE interpretation — the Phase-0 blueprint derivation is a different act, so the anchors-map notion is the correct carrier. Derivation from the Given/When/Then boundary becomes the absent-spec-seam fallback only. The canonical AC-line carrier also gains the latch-first clause: `infra/templates/intent-blueprint.template.md`'s AC-line guidance becomes "seam: latched from the spec when declared; derived when absent" (P7-style rationale: else newly authored blueprints default to the absent-seam degrade — the template is the carrier the Planner fills at the authoring moment). The PRE-freeze limb of the wrong-seam state gains its carrier HERE (the Phase-0 decision point): the latch sentence states the Planner REFUSES to freeze on a declared-but-wrong seam and escalates directly to the bc-side re-convergence lifecycle — the same endpoint as the post-freeze limb; no revision channel applies pre-freeze (that channel is the frozen-blueprint change path only). Escalation interface, specified honestly: the pre-freeze phase has NO loop-state machinery (init + `--blueprint-ref` run AT freeze), so the refusal is an AGENT ACT with a defined surface — the Planner does not run `loop_state.py init`, reports the named seam defect + the spec AC location back to the orchestrator/user in its dispatch context, and yields; the bc re-invocation is a USER act (the same human-gate placement as bc's own entry), consistent with "开始干活"的决定保留给人. No signal/state-machine path exists or is claimed. The orchestrator-facing mirror also lands: `plan-driven-mode.md` chaining-loop step 3's rich-path sentence ("seed the Phase-0 anchor from bc's spec … derive, don't re-imagine") gains a one-clause latch-first carve-out — "latch the declared seam when the spec AC carries one; derive only when absent" (workspace rule 8: the instruction must live at the decision-point doc the acting model reads; ADR #55 is the PRECEDENT instance of this rule for the step-4 dispatch table, not the authority for this step-3 edit).

### 4. pd `intent-blueprint.md` Blueprint Revision Channel — the wrong-seam routing sentence + trigger-bullet amendment + the ref-update tooling edit

Three edits: (a) the third trigger bullet gains an explicit wrong-declared-seam case — "has acceptance criteria that cannot be satisfied (incl. an AC whose declared seam boundary cannot observe its outcome)" — so the Coder/reviewer classifying the defect against the channel's trigger list finds the case named in-doc, not only in proposal prose (rule 8: the gloss must live at the decision-point doc); (b) one routing sentence: a declared-seam defect escalates to the bc-side re-convergence lifecycle — the spec is re-opened and corrected bc-side BEFORE the channel's re-freeze steps can run (the anchor authority forbids fixing the blueprint's seam while the spec still declares the wrong one). The re-sync object is the blueprint AC-line RE-LATCH (the channel's re-freeze re-reads the corrected spec and re-latches the seam), not the queue structure — `plan_queue.py sync` re-reads the QUEUE FILE's own markdown only (plan_queue.py sync: parse_queue_structure at queue_ref, plan-driven-mode.md CLI reference) and is NOT the spec re-read; it is not named as the re-sync mechanic. GAP, stated not asserted, WITH a picked remediation (recorded in the ADR entry): the blueprint-ref update mechanism does NOT exist today — `loop_state.py`'s `--blueprint-ref` is init-only and `set-blueprint-version` takes a version positional only, so a path-versioned re-freeze (`<task>-v<n>.blueprint.md`) leaves the recorded ref pointing at the STALE file. The landing ADDS a `loop_state.py set-blueprint-ref <path>` subcommand (edit (c) — the third named Fix-4 edit, enumerated here, not silent), shape specified: positional `<path>` mirroring `set-blueprint-version`'s positional convention; invoked at channel step 4 (the re-freeze step, alongside `set-blueprint-version`); records a `blueprint-ref-updated` event preserving the event-log + revision bookkeeping shape `set-blueprint-version` records (`blueprint-revised` event, `blueprint_revision` bump). Rejected alternative: re-init semantics at the channel's re-freeze — entangles the spec re-read with the channel's freeze lifecycle and clobbers status fields init resets; the subcommand is the cleaner separation (one field, one explicit act). Without these edits, the named endpoint in Fix 1b exists only in proposal prose — the channel's step 3 ("Escalate to the Planner + a human") carries zero bc routing today.

## Rejected alternatives (for the rule-6 ADR entry)

- (a) a plan-model `seam` field per item — duplication-or-inertness: the spec doc already carries the content (consumed via the authority chain), AND an `upstream_only` seam field would be INERT at the pd end — the schema's subset contract tags upstream_only fields "ignored by parallel-development" (plan-model.schema.json subset_tags + bc `plan_model.py`), and pd's rich path reads the SPEC via the queue's `authority_chain`, never plan-model fields. A field that is both duplicate and inert is dead weight.
- (b) leave the anchor in pd only (Option B alone) — the three recorded consequences stand; the wiki's upstream-anchoring point says the guard's precondition must anchor upstream of the consuming phase.
- (c) a new plan-reviewer finding kind — the existing `gap`/`blind-spot` kinds cover the seam defects; a new enum value ripples the schema + checker (rule 2).
- (d) the CONFIRMATION half of the pre-agreed-seam rule (mattpocock's "names the public boundaries it intends to test at and stops for your confirmation"; the wiki's "等待确认；硬规则是'不在未确认的接缝上写测试'") — REJECTED with the same rationale as pd ADR #56 Rejected (a) ("frozen anchors replace prose gates, consistent with rule 4"), extended here by Fix 2's adversarial seam-quality checks. The bc-side surfaces standing in for the confirmation step: the spec's own freeze (the declared seam is frozen spec content) + plan-reviewer's seam-quality checks (Fix 2, advisory). The human gate stays where the outcome axis already is — the human judges the spec's content, not the seam-agreement step. This rejection is recorded, not silent (rule 3).
